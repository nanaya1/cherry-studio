“智能体”与“智能体任务”的关系

资源中心 · 智能体

管理入口，回答“我有哪些 Agent、如何配置”。

  • 浏览、搜索、创建和编辑 Agent
  • 配置模型、Workspace、Skills 与 MCP
  • 选择 Agent 后可进入现有会话流程

欢迎页 · 智能体任务

使用入口，回答“我现在要让哪个 Agent 做什么”。

  • 从已有 Agent 中选择一个
  • 输入任务并发送
  • 首次发送后创建现有 Agent Session

两者使用同一套 Agent 数据：资源中心负责管理，欢迎页负责快速开始，不新增第二套智能体功能。

左侧历史会话

普通对话和智能体任务都展示在左侧边栏，但建议保留现有类型边界，分为两个可折叠分组：

  • 对话：现有 Assistant Topic，点击后进入普通聊天。
  • 智能体任务：现有 Agent Session，点击后进入 Agent 会话。
  • 分组可分别折叠；各自沿用现有标题、排序、置顶与删除能力。
  • 不把 Topic 和 Session 合并为新的统一数据模型。

  • 创建与编辑沿用现有对话框

  • 保留导入、详情和卸载流程
  • 不改变 Skill 数据与服务

连接器

提供现有 MCP 与消息渠道的导航入口。

  • 点击后打开对应现有页面
  • 详情与编辑流程保持不变
  • 不合并两套配置模型

本次明确不做

  • 不新增智能体、技能或连接器能力。
  • 不改变现有数据模型、服务层和会话创建流程。
  • 不新增线框稿中的技能数量、MCP 数量、工作区摘要等卡片字段。
  • 不把普通 Assistant 与 Agent 合并。
  • 不复制页面；优先复用现有组件，不能安全嵌入时只做路由跳转。

最小改动建议

修改现有应用壳，而不是新增一套布局页面。 新侧栏作为统一导航；右侧继续渲染现有路由内容。这样历史会话、Agent、Skills、MCP、消息渠道和定时任务都沿用原页面，仅改变用户到达它们的方式。
