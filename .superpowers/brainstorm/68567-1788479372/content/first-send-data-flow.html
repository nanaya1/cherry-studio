方案 A · 首次发送数据流

严格复用现有 Topic / Agent Session 创建入口与 ai.stream.open；新增代码只负责把“草稿态”衔接到现有会话态。

普通会话
1. 初始选择
最近使用 Assistant → 助手列表第一个
↓
2. 编辑完整草稿
文本、附件、模型、知识库、联网、MCP 等
↓ 点击发送
3. reuseOrCreateTopic
按所选 Assistant 精确复用空 Topic 或创建新 Topic
↓ 获得 topicId
4. 现有 Chat 发送控制器
构造同一 ai.stream.open 请求
↓ 接收 open ack
5. 当前 Tab 切换
/app/chat?topicId=…，正式页面接管流订阅
智能体任务
1. 初始不选择 Agent
选择 Agent 后解析其默认模型和 Workspace
↓
2. 编辑完整草稿
文本、附件、Workspace 文件、知识库、Skills 等
↓ 点击发送
3. reuseOrCreateSession
按 Agent + Workspace 精确复用，并沿用重复 Session 清理和 delivery gate
↓ 获得 sessionId / topicId
4. 现有 Agent 发送控制器
构造同一 ai.stream.open 请求
↓ 接收 open ack
5. 当前 Tab 切换
/app/agents?sessionId=…，正式页面接管 runtime
关键时序

先确认流已被接受，再切换页面

创建成功后不会立即清空草稿或先跳转。只有现有发送控制器收到 ai.stream.open 的成功确认，才清空草稿并将当前 Tab 切换为正式会话；这样可以避免路由切换导致首条消息丢失。

失败与并发规则

  • 空文本但有有效附件：沿用现有 Composer 规则，允许发送。
  • 未选择 Agent：发送按钮禁用，并使用现有选择控件提示选择。
  • 创建失败：停留在新建任务页，完整保留草稿、附件和选择状态。
  • 流打开失败：保留草稿；已创建的空会话继续由现有 placeholder 复用机制处理，不新增删除补偿。
  • 重复点击：从创建开始到 open ack 结束采用单次 in-flight 锁，避免重复 Topic / Session 和重复消息。
  • 选择变更：发送开始后冻结 Assistant / Agent / Workspace 快照，结束前禁止变更。
