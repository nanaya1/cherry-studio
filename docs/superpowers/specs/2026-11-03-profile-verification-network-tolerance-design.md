# 弱网账号验证与用户主动退出设计

日期：2026-11-03

状态：产品边界、整合设计及实施计划均已批准；代码已按本设计实施，测试与发布限制见第 14 节。

## 1. 意图与最终约束

内网不稳定时，客户端频繁出现列表刷新失败和 `Online profile verification is required`；随后退出登录可能遇到窗口提前关闭。本次修复误阻断及已发现的退出竞争，不扩展成认证系统重构。

用户已确认：

1. 运行中已经在线验证成功的同一账号，临时网络异常不撤销授权；不因超过原 5 分钟有效窗口而全局锁定。
2. 后台只负责验证、更新状态和提示；只有用户操作才触发退出登录、账号切换或业务运行时销毁。定时验证及凭据刷新均不得自动调用 logout、全量 teardown、relaunch 或 forceExit。
3. 确认登录失效、账号停用／全局访问资格撤销，或身份不再与当前账号空间一致时，主进程阻断业务，保留主窗口，显示居中阻断弹窗。阻断不是销毁运行环境。
4. 分组、角色变化不是全局账号失效，不弹全局阻断弹窗、不要求重登或重启；后台更新账号上下文及知识库相关权限和缓存。
5. 技能、MCP 与分组／角色无关，不新增动态托管机制；修正与既有复制安装语义冲突的客户端授权残留。远端服务自身认证不变。
6. 首次登录、冷启动、切换账号必须在线验证成功。不支持跨重启离线启动；网络失败保留凭据和验证重试机会，不假装账号失效。
7. 退出可靠性通过消除后台自动退出路径、加固既有用户退出流程解决；异常兜底不替代根因修复。

已接受的安全取舍：持续断网时，当前进程可能沿用最后一次成功验证的授权，无法即时得知服务端新发生的撤权。只有完整在线证据才能更新身份／权限；不能伪造成功，不能绕过服务端拒绝。

## 2. 当前实现与问题依据

- [BusinessAccessGate](../../../src/main/core/profiles/BusinessAccessGate.ts) 仅在未过期的 verified-online 状态放行，临时失败也会阻断；[运行上下文](../../../src/main/core/profiles/ProfileRuntimeContext.ts) 设置 5 分钟窗口。
- [ProfileOnlineMonitor](../../../src/main/enterprise/ProfileOnlineMonitor.ts) 每分钟复核，按普通 Error 文本分类，存在误判；[EnterprisePlugin](../../../src/main/enterprise/EnterprisePlugin.ts) 在不可恢复阻断时先全量 teardown 再提示。
- [OrgAuthManager](../../../src/main/enterprise/OrgAuthManager.ts) 的刷新失效路径自动 logout；group／role 变化也可能触发全局 gate；刷新与验证存在相互回调、自等待及旧凭据回写风险。
- [currentuser 传输](../../../src/main/enterprise/orgCurrentUserTransport.ts) 把 HTTP 状态压成普通错误；[ProfileAuthBroker](../../../src/main/enterprise/ProfileAuthBroker.ts) 的业务错误未统一分类。
- [IpcAdapter](../../../src/main/data/api/core/adapters/IpcAdapter.ts) 在所有 DataApi 请求前后检查 gate，GET 本地读取也受影响；它不能代表所有任务、工具入口已受控。
- [会话快照](../../../src/renderer/components/ResourceViewSourceProvider.tsx) 保留旧数据，但 [Sessions](../../../src/renderer/pages/agents/components/Sessions.tsx) 可能因元数据失败进入整体错误态；Agent 模式重试遗漏 refetchAgents。
- [Application](../../../src/main/core/application/Application.ts) 的 prepareProfileLogout 有返回登录期间的保活标记，prepareProfileSwitch 没有；[WindowManager](../../../src/main/core/window/WindowManager.ts) 全量销毁窗口后，Windows 可能因最后窗口关闭而退出。后台与用户退出竞争是当前代码可达路径，不等于现场每次闪退均已定位。
- [ProfileSwitchCoordinator](../../../src/main/core/profiles/ProfileSwitchCoordinator.ts) 及 [SwitchFence](../../../src/main/core/profiles/SwitchFence.ts) 已有持久化与失败封锁边界，应复用，不增加第二套账号切换框架。

## 3. Approaches：讨论与选择

### A. 沿用已验证授权，后台不退出，用户主动切换（用户选择）

暂时无法验证只改变连接健康；明确全局失效立即关业务授权并提示，但保持窗口和控制入口。组／角色变更局部更新知识库。用户操作是退出切换的唯一触发来源。

优点：符合弱网现场和现有产品语义，从设计上消除第二条自动退出路径；不再靠复杂协调兼容两套 teardown。

代价：运行中断网不能即时撤权；真正失效时需准确覆盖业务执行门禁，而不能只靠销毁服务或前端遮罩。

### B. 固定离线宽限期，到期全局阻断（不采用）

只缓解短时抖动，时间经过本身不能证明账号失效，不符合已确认原则。

### C. 后台失效自动停止运行时，再协调用户退出（撤回）

增加自动 teardown 和窗口交接竞争；与用户明确的“后台不退出”约束冲突。

敏感操作专门实时验证、分组变化全局重建、通用权限热更新体系均不在本次范围。

## 4. 错误与证据分类

| 事件 | 已验证进程的处理 | 全局弹窗／退出 |
| --- | --- | --- |
| DNS／连接错误、超时、5xx、429 | 保留授权，后台重试 | 不弹全局失效框，不退出 |
| 非 JSON、缺字段、意外响应、语义未知的 4xx | 不采纳不完整结果，记录诊断并重试 | 不推断失效，不退出 |
| 权威认证端点明确拒绝，必要的有界恢复仍确认无效 | 全局阻断并说明重新登录原因 | 阻断弹窗，等待用户操作，不自动 logout |
| 完整可信结果表明账号停用或全局访问资格撤销 | 全局阻断并说明原因 | 阻断弹窗，不自动退出 |
| 完整可信结果表明 user／server identity 改变 | 阻止新身份进入原账号数据空间 | 说明身份不一致，引导用户显式重登，不自动换账号 |
| 同一身份的 group／role 变化且账号仍有效 | 更新账号上下文，失效知识库相关旧权限缓存与租约 | 不全局阻断，不重启 |
| 单个知识库／业务资源拒绝 | 只拒绝该操作；不从资源错误推断全局失效 | 局部提示 |
| 用户主动退出／换账号 | 关闭旧授权、使在途结果失效，执行既有切换流程 | 用户操作才触发切换 |

技术核实是实现方责任：查明服务端认证端点、错误码及 401／403 的权威语义。不能因为任意接口返回 403，或错误消息出现 token／401 字样，就撤销全局授权。缺少已确认契约时视为不确定并记录限制，不虚构服务器能力；若因此无法兑现明确失效识别，先报告契约缺口，不宣称已完成验收。

统一使用结构化结果，保留请求阶段、端点来源、HTTP status、协议业务码和已验证结论。先校验响应形状及字段含义，再判断停用、身份／权限变化；日志不记录 Token、Cookie 或完整敏感响应。

## 5. 授权状态与复核机制

授权与验证健康是两个维度，不强制新增两套存储：

- 授权：未验证、已验证、明确失效、用户切换中。
- 验证健康：正常、复核中、暂时不可用／不确定。

已验证的 authenticated business Profile，在没有明确全局失效或主动退出时允许原有业务；临时失败、复核中及时间流逝不改变授权。最后成功时间只作诊断，不生成虚假续期。进程休眠后恢复仍遵守同一规则，并调度复核。

明确失效后，普通后台重试、列表重试以及迟到成功不能解除阻断。恢复须由用户发起显式重新认证并完成现有安全启动流程。组／角色变更不进入此终止状态。

建议实现默认值（工程选择，非用户另行指定）：

- 健康时沿用 60 秒复核，单次验证请求保留 10 秒超时。
- 暂时失败后按 2、5、10、30 秒退避，后续约 30 秒一次，加入有界抖动；成功恢复正常频率，适当遵守 Retry-After。
- 在认证管理边界共享同一在途复核任务；手动、后台和恢复唤醒不重复并发验证。
- 验证与 Token 刷新分离，分别合并并发且不能互相回调等待。Bearer 每轮必要时最多受控刷新一次、重试验证一次；Cookie 不进入 Bearer 刷新。
- 刷新响应先校验；验证使用明确的凭据快照。提交结果同时核对账号代际和凭据版本，不能用较早验证携带的旧 Token 覆盖新 Token。
- Token 本地到期只是刷新触发条件，不单独证明账号失效。刷新网络失败不得自动 logout。
- 沿用现有 epoch／生命周期清理，退出或停止后丢弃旧结果；无需建立第二套通用并发框架。

## 6. 明确失效：锁业务，不销毁宿主

全局失效时立即限制业务，但保持窗口、状态读取和用户恢复操作：

1. 关闭统一主进程业务授权。
2. 拒绝新的业务读写、任务接纳／出队／执行以及后续工具调用；不能只挡 DataApi 或 renderer。具体入口清单由实施计划根据现有调用链列出。
3. 对可取消的在途执行发出取消；已提交远端操作不假装撤回，不自动重放。取消／清理的最小必要状态写入不得被业务门禁反锁，且仍受原操作身份和生命周期约束，不能形成任意写入豁免。
4. 保留主窗口、WindowManager、状态控制 IPC 和重新登录所需能力，不调用 stopAll／destroyAll／prepareProfileSwitch。
5. 当前主窗口显示一个居中阻断弹窗，原界面在遮罩后。无 Esc、点击遮罩或关闭按钮绕过；即使弹窗未渲染或另一业务窗口仍在，主进程门禁也保持阻断。正常用户关闭应用仍允许，不把“不许关弹窗”实现成“不能退出应用”。

弹窗内容与动作：

- 凭据确认无效：登录已失效，本地数据不会删除；提供重新登录和退出应用。
- 账号停用／全局资格撤销：说明需联系管理员；提供使用其他账号登录和退出应用。
- 身份不一致：说明需重新确认账号；通过显式登录进入正确隔离空间。

资源级知识库拒绝不使用上述全局弹窗。第一版不新增全局弱网横幅、新设置或 UI 重设计；阻断弹窗复用 UI 包现有对话框组件，并遵守 DESIGN.md、i18next。

## 7. 分组／角色、知识库与技能 MCP

### 知识库局部更新

账号仍有效且身份不变时，接受完整可信的新 group／role，更新内存、持久化会话与必要授权上下文，失效旧知识库授权租约及相关缓存。旧分组的在途结果不得写回新上下文。

- 已打开页面刷新组织知识库列表；Agent 的 kb_list／kb_search／kb_read 同样使用新上下文，不能只做页面级处理。
- 后续访问由服务端按最新权限决定，不因为角色名变化就自行推断每个资源是否失权。
- 明确无权的资源局部提示，不继续用旧缓存绕过服务端拒绝；临时网络失败不显示成无权限。
- 仅重新读取数据，不自动重放分享、删除等业务写操作。
- 无关的会话、本地知识库、任务和工具不因 group／role 变化全局暂停，不要求重启。

### 技能与 MCP 保持本地副本语义

分组／角色不作为客户端停用技能和 MCP 的条件。当前 SkillService、McpRuntimeService 及目录安装链中的 entitlement 残留，按最小范围修正，不新增组织托管或停用体系，不顺手清除历史记录。

组织目录的服务端响应仍如实处理，不能仅凭客户端携带认证就推断服务端存在分组裁剪。已安装副本与目录请求分开；MCP 远端服务自身凭据、用户启停、工具审批和独立访问控制保持不变。

此规则仅排除分组／角色关联，不等于账号明确全局失效后还能绕过客户端整体业务门禁执行工具。

## 8. 用户主动退出：复用唯一正常流程

只有用户选择退出登录、重新登录或其他账号登录才启动退出切换。后台自动失效处理入口一律转到状态与提示，不再自动 teardown；不再为两条退出流程设计复杂协调器。

既有用户退出流程只加固必要部分：

1. 用户操作入口同步标记正在退出并合并重复请求，先使旧认证结果失效；在任何网络等待、落盘 await 之前建立适当的切换保活与操作所有权。保护与持久化顺序由实现按现有事务边界安排，不能绕过 durable logout intent。
2. 沿用退出意图、凭据隔离、切换日志与 pointer 的持久化规则。不恢复用户已明确退出的旧凭据，不跳过失败安全边界。
3. 远端注销与本地退出解耦，使用已捕获身份快照及有界请求；远端网络失败不能卡住本地退出或令应用消失。不能让延后清理清除新登录的凭据／Cookie。
4. 正常停止旧业务运行时并创建登录窗口，进程在无业务窗口期间继续存活。现有 returningToLogin 机制应复用，保护持续到登录窗口真正就绪且已交接，不在创建函数刚返回时过早解除。
5. 旧请求、旧窗口回调不得重新放行、重复弹框或关闭新登录窗口。优先复用现有 epoch、窗口 owner 和 superseded 防护。
6. 不自动续跑中断任务、不自动重放远端写操作；保留本地会话、文件，尽可能保留草稿且不跨账号暴露。

异常最后防线：磁盘／生命周期不可恢复错误不允许假装退出成功，也不能解锁半销毁运行时。主窗口尚可用时在那里说明；已经不可用时通过生命周期之外的原生对话框承接原因和用户选择的重启／退出。不得仅写日志后无提示消失。不新增通用恢复系统；现有 bootstrap 和原生对话框足够则复用。

已发现的后台与用户 teardown 竞争应被移除并用测试证明，而不是留给用户反复重启解决。不能承诺未定位的现场所有崩溃都由这一修改消除。

## 9. 冷启动在线验证及重试

磁盘上的旧会话不能直接放行业务。临时验证失败时：

- 在隔离的启动／登录控制界面提示暂时无法连接账号服务，业务运行时不启动。
- 保留待验证账号、凭据及安全的启动重试上下文，不因临时故障提交用户已退出的语义或清空凭据。
- 提供实际可执行的重试验证入口；成功后走正常启动。不能只有重试文案但没有原候选账号可重试。
- 用户主动选择其他账号或退出当前账号时，才进入对应显式流程。未验证数据不暴露给登录界面。
- 启动控制面不依赖已启动业务服务或被门禁阻断的 DataApi；复用现有 bootstrap 模式并最小扩展。

## 10. 列表恢复与跨进程契约

沿用 IpcApi 企业命名空间。共享契约放 shared，renderer 不直接改变门禁；查询状态、复核重试、取消、退出、认证等控制能力不能被业务门禁一并封死。事件携带账号代际并支持初始状态查询，避免错过广播或旧账号事件。

复核请求／状态事件优先扩展既有企业契约；最终路由命名由实施计划确定，不新增 DataApi 非数据库端点。

- 临时复核异常不制造业务 403，不重复 toast；真实联网业务失败仍可局部提示。
- 会话与分组元数据均有旧值时，保留可用内容；没有旧值时保留真实加载错误，不伪造空列表。
- 不同时声称“仍显示旧内容”又用元数据错误替换整块列表。
- 列表重试触发去重的后台复核，同时重读已获准的本地列表，不等待网络验证完成；补齐 Agent 分组 refetchAgents 和工作目录依赖，读取可并行。
- 从暂时异常恢复正常时刷新相关已挂载列表；不每次健康轮询全局清缓存，不自动重试写操作。
- 账号明确全局失效时统一由阻断提示承接，列表重试不解锁。

## 11. 范围控制及仓库要求

中等规模、跨主进程与少量共享／renderer 文件；关键是状态与窗口交接，不做认证架构重写。

不改数据库结构、不迁移用户数据、不安装新依赖、不重做登录页面、不引入离线许可证、不建立动态技能 MCP 托管、不增加分组变化全局重建机制。退出及缓存修改均必须与本设计的具体问题关联。

实现同步更新 `.mea/customizations.yml` 的生产触点与聚焦测试，使用稳定 MEA marker；禁用既有逻辑按项目要求注释保留；不覆盖用户现有修改。日志走 loggerService、资源依现有生命周期清理、新 UI 使用 @cherrystudio/ui 且遵守 DESIGN.md，所有新增文案走 i18next。禁止提交、推送或重写已发布迁移，除非另获明确授权。

## 12. 验收标准

1. 已验证账号经历单次和长于原 5 分钟的超时／DNS／503／429，仍可读取写入本地业务数据；无全局失效框、无自动 logout、无全量 teardown。
2. 完整证据确认凭据失效或账号停用：主进程立即阻断业务、任务与后续工具；主窗口保留、提示一次，无自动退出。不能只靠 DataApi mock 证明覆盖。
3. 后台刷新确认失效与定时监视失效行为一致，均不直接 logout；普通资源 403、解析错误及未知响应不误触全局阻断。
