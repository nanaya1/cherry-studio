# Sub2API/Mass 与客户端 Token 统计、模型配置最小闭环

> 本文用于说明：如何在 Sub2API/Mass 管理后台完成上游账号、分组、模型和 API 密钥配置，再接入客户端发起真实请求，并分别在 Mass 与客户端核对 Token 统计。
>
> **版本说明：** Mass 侧路径和字段依据当前 Sub2API 管理后台实现整理。不同部署版本的菜单位置可能略有差异，但核心关系保持一致：上游账号关联分组，API 密钥绑定分组，分组控制模型白名单、映射和路由。

## 1. 最小闭环目标

最小闭环只有四个阶段：

1. **Mass 上游配置**：添加一个可用的上游账号，并完成连接测试。
2. **Mass 模型与权限配置**：创建分组，关联上游账号，配置模型白名单或模型映射，再创建绑定该分组的 API 密钥。
3. **客户端接入**：在客户端添加供应商，填写 Mass API Host、API Key，并添加同名模型 ID。
4. **双端统计验证**：发起一次成功请求，分别在 Mass“使用记录”和客户端“用量统计”确认请求数和 Token 大于零。

闭环成功条件：

- 客户端模型选择器可以选中目标模型；
- 测试请求正常返回；
- “设置 → 用量统计”显示总请求数和总 Token；
- 按供应商或模型分组可以定位本次请求。

## 2. 名称与实现边界

在当前客户端代码中：

- `sub2api` 是外部模型网关，不是本仓库内的服务端模块；
- 客户端内置的雪浪工匠供应商 ID 是 `xuelang`，显示名称是“雪浪工匠”；
- `aimass` 仅出现在模型图标资源中，不是当前客户端的供应商 ID，也不是 Sub2API/Mass 配置入口；
- 如果实际使用的是雪浪工匠 OAuth 网关，应走“雪浪工匠授权登录”流程；
- 如果实际使用的是独立部署的 Sub2API/Mass OpenAI 兼容入口，应走“自定义供应商 + API Key + 模型”流程。

本文重点描述第二种可迁移的最小闭环，并在最后补充雪浪工匠 OAuth 的差异。

## 3. Mass 侧配置模型与 API 密钥

Mass 侧最小可调用链路是：

```text
上游账号 → 分组 → API 密钥 → 客户端请求
```

API 密钥不直接绑定模型。密钥先绑定分组，再由分组的模型白名单、模型映射和模型路由决定该密钥能调用哪些模型以及实际转发到哪个上游账号。

### 3.1 添加上游账号

操作路径：**管理员后台 → 账号管理 → 添加账号**。

1. 登录 Mass 管理后台。
2. 在左侧菜单进入 **账号管理**。
3. 点击 **添加账号**。
4. 填写 **账号名称**。
5. 选择上游 **平台**，例如 OpenAI、Anthropic、Gemini 或实际使用的平台。
6. 选择 **账号类型**，例如 OAuth、API Key 或 Setup Token。
7. 按认证类型完成授权，或填写上游 API Key、Base URL 等凭据。
8. 在 **关联分组** 中先留空；也可以在分组创建后返回编辑并关联。
9. 保存账号。
10. 在账号操作中执行 **测试账号连接**。

最小成功判定：

- 测试结果显示连接成功；
- 账号状态为启用或正常；
- 账号允许参与调度；
- 页面能够显示该账号的可用模型或上游额度信息。

### 3.2 创建分组并关联账号

操作路径：**管理员后台 → 分组管理 → 创建分组**。

1. 进入 **分组管理**。
2. 点击 **创建分组**。
3. 填写 **名称**，例如 `cherry-openai`。
4. 选择与上游账号一致的 **平台**。
5. 设置 **费率倍数**；最小验证可使用默认值或 `1`。
6. RPM、日限额、周限额、月限额等没有管控要求时可暂不设置。
7. 保存分组。
8. 返回 **账号管理**，编辑刚创建的上游账号。
9. 在 **关联分组** 中勾选该分组并保存。

也可以在创建分组时使用“从分组复制账号”，但最小闭环建议直接在账号编辑页设置关联分组，关系最清晰。

成功判定：

- 分组处于启用状态；
- 分组平台与账号平台一致；
- 上游账号的“关联分组”中包含目标分组；
- 分组中至少存在一个状态正常、可调度的上游账号。

### 3.3 配置分组模型

仍在 **分组管理** 中编辑目标分组，根据实际需求配置以下项目：

| 配置项 | 最小闭环用法 |
| --- | --- |
| 模型白名单 | 限制客户端可请求的模型；开启后必须至少填写一个模型 ID |
| 默认映射模型 | 未命中特定映射时转发到的默认上游模型 |
| 精确模型映射 | 将客户端请求模型映射为上游真实模型，例如 `qwen3-8-27b` → `gpt-5.6` |
| 模型路由 | 为某个模型指定优先使用的上游账号 |

不需要改名时，最简单的配置是：

1. 在 **模型白名单** 中填写上游真实支持的模型 ID。
2. 不配置模型映射，客户端直接使用同一个模型 ID。
3. 不配置模型路由，让分组从已关联的可调度账号中选择。

需要对客户端隐藏上游模型名时：

1. 在模型白名单中加入准备提供给客户端的模型 ID。
2. 在精确模型映射中填写“客户端模型 ID → 上游真实模型 ID”。
3. 如需固定账号，再在模型路由中选择优先账号。
4. 保存分组。

> 开启模型白名单后，如果列表为空或未包含客户端请求的模型，Mass 会拒绝请求。模型映射的目标模型必须是上游账号真实支持的模型。

### 3.4 创建客户端 API 密钥

操作路径：**API 密钥 → 创建密钥**。普通模式下入口位于用户侧“我的账户”，简单模式下管理员侧边栏也会直接显示“API 密钥”。

1. 进入 **API 密钥**。
2. 点击 **创建密钥**。
3. 填写 **名称**，例如 `cherry-client`。
4. 在 **分组** 中选择上一节创建的分组。
5. 保持密钥状态为启用。
6. 根据需要配置 IP 白名单或黑名单、额度、5 小时/1 天/7 天速率限制；最小验证可暂不限制。
7. 创建并妥善保存生成的密钥。

成功判定：

- API 密钥状态为启用；
- API 密钥已绑定目标分组；
- 目标分组中存在可调度账号；
- 目标模型在分组白名单内，或能命中模型映射。

Mass 侧交付给客户端的最小参数如下：

```text
API Host: https://gateway.example.com/v1
API Key: Mass 创建的客户端密钥
Model ID: 分组允许客户端请求的模型标识
Endpoint 类型: 与分组平台和上游协议一致
```

> API Key 是客户端访问 Mass 的凭据，不是上游厂商密钥。不要将任何密钥写入代码、提交到 Git、发送到群聊或放入截图。

### 4.3 Endpoint URL 填写规则

**Endpoint URL 只填写网关主机或基础地址，不要填写完整请求路径。**

正确示例：

```text
https://gateway.example.com
https://gateway.example.com/v1
```

错误示例：

```text
https://gateway.example.com/v1/chat/completions
```

客户端会根据 Endpoint 类型自动拼接 `chat/completions`、`responses` 等请求路径。如果把完整路径再次填入，可能出现双重路径，例如：

```text
https://gateway.example.com/v1/chat/completions/chat/completions
```

这类错误通常表现为 404、路由不存在或请求无法到达模型。

### 4.4 保存供应商

1. 填写供应商名称。
2. 填写至少一个文本类 Endpoint URL。
3. 填写 API Key。
4. 点击 **添加** 或 **保存**。

**成功判定：** 对话框关闭，左侧供应商列表出现新供应商，详情页显示 API Host 和 API Key 配置区域。

> API Key 在创建时可能允许留空，但没有有效 Key 时，模型请求通常会返回鉴权失败。为完成最小闭环，建议创建时直接填写。

4. 填写服务端实际存在的 **Model ID**。

如果客户端支持为模型填写定价，建议补充输入 Token 和输出 Token 单价。

- Token 数量和请求数仍可统计；
- 成本卡片可以显示费用；
- 未配置定价且网关未返回成本时，成本可能为空或显示“无”；
- 成本为空不代表 Token 统计失败。

**请求成功判定：** 页面正常显示模型回复，没有出现以下错误：

## 7. 在 Mass 查看 Token 统计

### 7.1 管理员查看整体用量

操作路径：**管理员后台 → 使用记录**。

1. 登录 Mass 管理后台。
2. 在左侧菜单进入 **使用记录**。
3. 将时间范围调整到包含刚才测试请求的时间。
4. 在顶部指标卡确认 **总请求数** 和 **总 Token** 已增加。
5. 进入 **用量明细**，查找刚才的请求记录。
6. 使用筛选条件缩小范围，优先选择刚创建的 **API 密钥**、**分组** 或调用的 **模型**。
7. 打开或查看明细，核对用户、API 密钥、上游账号、请求模型、分组、Token、费用、延迟和请求时间。

管理员统计页面包含：

- 总请求数；
- 总 Token，包含输入、输出、缓存创建和缓存读取 Token；
- 总费用、实际费用和上游账号成本；
- 平均耗时；
- 模型、分组和端点分布；
- Token 用量趋势；
- 用量明细、错误请求和用户 Token 排行。

可用筛选项包括：用户、API 密钥、模型、上游账号、分组、请求类型、计费类型、计费模式、上游模型不一致状态和时间范围。管理员还可以导出 Excel 明细。

### 7.2 最小闭环成功判定

本次请求应同时满足：

- **总请求数**至少增加 1；
- **总 Token**大于 0；
- 用量明细能定位到刚创建的 API 密钥；
- 分组为客户端密钥绑定的目标分组；
- 请求模型为客户端发送的 Model ID；
- 上游账号为该分组中实际被调度的账号；
- 映射场景下，可以区分请求模型、映射模型或上游模型；
- 错误请求页没有本次调用对应的失败记录。

### 7.3 用户和密钥自助查看

除管理员视角外，还可使用以下入口：

- 登录用户进入 **使用记录**，查看本人密钥产生的用量和错误请求；
- 打开公开的 **密钥用量查询** 页面，输入 API Key 查看该密钥用量；
- 用户视角不显示上游账号成本，也不能按其他用户或上游账号筛选。

### 7.4 Token 统计与上游额度的区别

| 数据 | 查看路径 | 说明 |
| --- | --- | --- |
| Mass 本地 Token 统计 | 管理员后台 → 使用记录 | 每次经过 Mass 的请求、Token、费用和归属记录 |
| 用户自身 Token 统计 | 用户端 → 使用记录 | 当前用户的请求和 Token 数据 |
| 单密钥用量 | 密钥用量查询 | 指定 API Key 的累计用量 |
| 上游账号额度 | 管理员后台 → 账号管理 | 上游厂商返回的 5 小时、7 天、月度额度或余额等 |

“使用记录”有 Token 不代表上游配额充足；“账号管理”显示上游额度充足，也不代表当前 API 密钥的分组、额度和模型权限配置正确。排查时应分别核对。

### 7.5 Mass 没有统计数据时

按以下顺序排查：

1. 客户端请求是否真正经过当前 Mass 地址；
2. 请求使用的是否是 Mass 创建的客户端 API Key，而不是上游厂商密钥；
3. API 密钥是否启用并绑定正确分组；
4. 分组是否关联至少一个正常、可调度的上游账号；
5. 模型是否在白名单内，映射目标是否真实存在；
6. 使用记录的时间范围是否包含测试时间；
7. 是否按了错误的用户、密钥、分组、账号或模型筛选；
8. 在 **错误请求** 中是否能找到 401、模型无权限、调度失败或上游额度不足记录。

## 9. 最容易出错的地方

### 9.1 Endpoint URL 填了完整路径

**表现：** 404、路由不存在、双重 `chat/completions` 路径。

**处理：** 删除完整接口路径，只保留网关主机或基础地址。

### 9.2 只创建供应商，没有添加并启用模型

**表现：** 供应商存在，但模型选择器没有可选模型，Token 统计始终为零。

**处理：** 在供应商详情页添加服务端实际存在的 Model ID，并启用模型。

### 9.3 没有配置模型定价

**表现：** 请求数和 Token 有数据，但总成本为空或显示“无”。

**处理：** 补充模型定价，或确认网关是否会返回成本信息。成本为空通常不影响 Token 和请求数统计。

### 9.4 Mass 上游账号没有关联分组

**表现：** API 密钥和分组都存在，但请求时没有可调度账号。

**处理：** 进入 **账号管理** 编辑上游账号，在“关联分组”中勾选 API 密钥绑定的分组。

### 9.5 Mass 模型白名单或映射错误

**表现：** 请求提示模型无权限、模型不存在，或映射后的上游模型调用失败。

**处理：** 确认客户端 Model ID 位于分组模型白名单内；如配置了模型映射，确认目标模型是上游账号真实支持的模型。

### 9.6 把上游厂商密钥交给客户端

**表现：** 请求绕过 Mass，Mass“使用记录”中没有对应 Token 数据，或者客户端直接访问了上游厂商。

**处理：** 客户端必须使用 Mass 在“API 密钥”页面生成的客户端密钥；上游厂商密钥只保存在 Mass 的上游账号配置中。

## 10. 常见问题

| 问题 | 可能原因 | 处理方法 |
| --- | --- | --- |
| 创建供应商时提示缺少文本 Endpoint | 未填写文本类 Endpoint URL | 至少填写一个文本 Endpoint URL |
| 保存后请求 401 | API Key 无效、过期或未保存 | 重新确认并保存 API Key；检查服务端 Key 状态 |
| 请求 404 | Endpoint URL 包含完整路径，客户端又自动拼接 | 只保留网关主机或基础地址 |
| 请求提示模型不存在 | Model ID 拼写错误或服务端未发布 | 使用服务端真实模型 ID，区分大小写和连字符 |
| 请求提示无权限 | API Key 绑定的分组未允许目标模型 | 检查密钥绑定分组及分组模型白名单 |
| Mass 提示没有可调度账号 | 上游账号未关联分组，或账号被禁用、限流 | 将账号关联到目标分组，并检查账号状态和上游额度 |
| 映射后提示模型不存在 | 模型映射的目标模型不是上游真实模型 | 修正分组或账号级模型映射 |
| 供应商有模型但请求失败 | Endpoint 类型与服务端协议不一致 | 选择与服务端兼容协议匹配的 Endpoint 类型 |
| 请求成功但 Mass Token 为零 | 客户端绕过 Mass，或使用记录时间/筛选条件错误 | 核对 API Host 和 Mass 客户端密钥；清除筛选并调整时间范围 |
| 请求成功但客户端 Token 为零 | 请求未完成客户端统计落库、时间范围不匹配或页面未刷新 | 确认请求完整返回；刷新页面；调整日期范围 |
| Token 有数据但成本为空 | 模型没有定价，且网关未返回成本 | 配置模型定价；这不代表 Token 统计失败 |
| 统计中找不到供应商 | 当前按其他维度分组或请求未落库 | 改为按供应商分组，确认请求成功并刷新页面 |

## 11. 雪浪工匠 OAuth 模式差异

如果使用的是客户端内置的雪浪工匠 OAuth 网关，而不是独立 Sub2API/Mass API Key，最小流程如下：

1. 进入 **设置 → 模型服务 → 雪浪工匠**。
2. 点击 **雪浪工匠授权登录**。
3. 在浏览器中完成登录和授权。
4. 返回客户端，确认显示账号信息和 **退出登录**。
5. 在同一页面下方启用模型。
6. 发起一次模型请求。
7. 进入 **设置 → 用量统计**，按供应商分组查看雪浪工匠。

授权成功判定：

- 显示账号昵称或邮箱；
- 显示余额或余额占位状态；
- 出现“退出登录”；
- 雪浪工匠供应商已启用。

当前客户端代码中，雪浪工匠的供应商 ID 是 `xuelang`，默认网关地址为：

```text
https://api.xuelanglm.com
```

雪浪工匠 OAuth 地址由客户端运行时固定管理，普通用户不需要在界面手工配置 OAuth Endpoint。当前雪浪工匠授权卡片不提供充值按钮，额度管理应通过雪浪工匠官方平台完成。

## 12. 管理员验收清单

### Mass 侧

- [ ] 已在“账号管理”添加上游账号并通过连接测试；
- [ ] 上游账号处于启用、可调度状态；
- [ ] 已在“分组管理”创建与账号平台一致的分组；
- [ ] 上游账号已关联目标分组；
- [ ] 分组模型白名单包含客户端 Model ID，或已配置正确的模型映射；
- [ ] 已创建 Mass 客户端 API 密钥并绑定目标分组；
- [ ] API 密钥处于启用状态，额度和速率限制允许测试请求；
- [ ] 已确认客户端使用的 API Host 和兼容协议；
- [ ] “使用记录”中总请求数和总 Token 已增加；
- [ ] 用量明细可定位 API 密钥、分组、模型和实际上游账号；
- [ ] 如需成本统计，已配置相应定价。

### 客户端

- [ ] 已创建自定义供应商；
- [ ] Endpoint URL 只填写主机或基础地址；
- [ ] API Key 已保存；
- [ ] 目标模型已添加并启用；
- [ ] 对话页可以选中目标模型；
- [ ] 测试请求正常返回；
- [ ] “用量统计”总请求数大于 0；
- [ ] “用量统计”总 Token 大于 0；

- [ ] 已确认成本为空时不等同于 Token 统计失败。

## 13. 一页式快速操作

```text
Mass：账号管理 → 添加上游账号 → 测试连接成功

Mass：分组管理 → 创建分组 → 账号关联分组
        ↓
Mass：配置模型白名单/映射 → API 密钥 → 创建密钥并绑定分组
        ↓
客户端：设置 → 模型服务 → 添加自定义供应商
        ↓

        ↓

        ↓

        ↓
Mass：使用记录 → 按 API 密钥/分组/模型筛选
        ↓
客户端：设置 → 用量统计 → 按供应商/模型分组
        ↓

```
